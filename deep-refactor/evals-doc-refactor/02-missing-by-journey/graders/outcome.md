Missing docs are found by walking a real contributor journey, not by imagining an outline, and every claim must be verified rather than invented. Check all of:
- It does NOT produce a generic "what a project should document" CONTRIBUTING.md from an imagined outline of sections.
- It scopes the gap to what a contributor would actually hit — here, that nothing documents how to run the tests — rather than to a checklist of ideal sections.
- It does not invent unverified facts (test commands, CI, branch rules); it either asks for them, marks them to verify, or leaves them out.
- Any doc it adds or proposes names an owner and how it will be kept true.
Fail if it writes a generic template of sections, or fills it with invented commands.
